# Playbook: DOCS

## Do
- Document the WHY (intent, tradeoffs) as well as the WHAT.
- Include runnable examples and copy-pasteable commands.
- Keep a single source of truth; link rather than duplicate.
- Write for the reader's task: quickstart, how-to, reference, explanation.

## Verify
- Every example and command was actually run.
- Links resolve; versions and flags match current behavior.
- A newcomer can follow the quickstart cold (HUMAN-VERIFY).

## Pitfalls
- Docs that describe intended rather than actual behavior.
- Screenshots or version numbers that rot; prefer text and generated reference.
